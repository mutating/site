Аннотации типов Python описывают больше, чем можно проверить через `isinstance()`: объединения и параметризованные коллекции требуют отдельной обработки. Диспетчеризации, регистрации и конфигурации часто достаточно дешёвой проверки совместимости — без рекурсивной валидации, преобразований и системы схем.

Локальная функция задаёт в каждом проекте разные правила. [Typeguard](https://typeguard.readthedocs.io/en/latest/), [Beartype](https://beartype.readthedocs.io/) и [Pydantic](https://docs.pydantic.dev/latest/concepts/type_adapter/) решают более широкую задачу через рекурсивные проверки, enforcement или преобразование — больше, чем нужно недорогому предикату.

[simtypes](https://github.com/mutating/simtypes) — Python-библиотека без зависимостей для этой конкретной проверки. Она предоставляет один предикат, который понимает обычные классы, объединения, optional-типы, `Any`, `None` и наблюдаемый внешний тип параметризованных аннотаций. [Релиз](https://github.com/mutating/simtypes/releases/tag/0.0.1) доступен на GitHub.

## Поддерживаемые runtime-проверки

Библиотека экспортирует `check(type, value) -> bool`, где первым аргументом передаётся тип:

```python
from simtypes import check

check(int, 42)                    # True
check(int | None, None)           # True
check(list[str], [1, 2, 3])       # True
```

Последний результат намеренный: `list[str]` проверяет только то, является ли значение списком. Обычные классы проходят через `isinstance`, а для `Any`, `None`, объединений, optional-аннотаций и внешних типов есть явные правила.

Поэтому стоимость проверки не растёт с длиной коллекции, но simtypes не подходит для недоверенных вложенных данных или полной статической аннотации.

Здесь нет runtime-зависимостей, декораторов, import hooks, преобразования значений и схем: вызывающий код получает `bool` и сам решает, что с ним делать.

## Сравнение с полноценными средствами валидации

Более широкие инструменты лучше подходят для полной валидации. Например, [Runtype](https://runtype.readthedocs.io/en/stable/validation.html) рекурсивно проверяет коллекции, а simtypes намеренно этого не делает.

Для одного места вызова достаточно локальной функции. simtypes полезен, когда несколько библиотек должны разделять и тестировать одну политику.

## Для чего предназначен simtypes

simtypes предназначен для runtime-инфраструктуры, которой нужна дешёвая проверка совместимости. Диспетчеризация, регистрация плагинов и конфигурация могут разделять одно правило без полноценного фреймворка валидации.

## Что дальше

Проект охватит больше runtime-типов и необязательных преобразований, сохраняя дешёвую проверку только наблюдаемых во время выполнения свойств.
