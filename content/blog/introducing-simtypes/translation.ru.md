Аннотации типов Python описывают больше, чем можно напрямую проверить через `isinstance()`: даже объединение или параметризованная коллекция требуют отдельной обработки. Диспетчеризации, регистрации или конфигурации часто нужен такой ответ во время выполнения, но достаточно дешёвой проверки «совместимо или нет» — без рекурсивной валидации, преобразования значений, декораторов и целой системы схем.

Вспомогательная функция на основе `isinstance()` и `typing.get_origin()` может обработать несколько видов аннотаций, но каждый проект при этом задаёт немного разные правила. [Typeguard](https://typeguard.readthedocs.io/en/latest/), [Beartype](https://beartype.readthedocs.io/) и [Pydantic](https://docs.pydantic.dev/latest/concepts/type_adapter/) решают более широкую задачу через рекурсивные проверки, автоматическое применение контрактов или преобразование значений. Такое дополнительное поведение не нужно, когда диспетчеризации или регистрации плагинов требуется только предсказуемый и недорогой предикат.

[simtypes](https://github.com/mutating/simtypes) — Python-библиотека без зависимостей для этой конкретной проверки. Она предоставляет один предикат, который понимает обычные классы, объединения, optional-типы, `Any`, `None` и наблюдаемый внешний тип параметризованных аннотаций. [Релиз](https://github.com/mutating/simtypes/releases/tag/0.0.1) доступен на GitHub.

## Поддерживаемые runtime-проверки

Библиотека экспортирует `check(type, value) -> bool`, где первым аргументом передаётся тип:

```python
from simtypes import check

check(int, 42)                    # True
check(int | None, None)           # True
check(list[str], [1, 2, 3])       # True
```

Последний результат намеренный. `list[str]` задаёт вопрос «это список?», но не перебирает элементы и не проверяет, что каждый из них — строка. Обычные классы проходят через `isinstance`, а для `Any`, `None`, объединений, optional-аннотаций и внешнего runtime-типа параметризованных аннотаций существуют небольшие явные правила.

Поэтому стоимость проверки коллекции предсказуема и не растёт с её длиной. Но по той же причине simtypes не подходит для проверки недоверенных вложенных данных или полной статической аннотации. Такая валидация находится за пределами его задачи.

В итоге получается небольшой checker без runtime-зависимостей, декораторов, import hooks, приведения значений и компилятора схем. Вызывающий код получает булево значение и сам решает, что с ним делать.

## Сравнение с полноценными средствами валидации

Упомянутые выше более широкие инструменты лучше, когда нужна полная валидация. Например, [Runtype](https://runtype.readthedocs.io/en/stable/validation.html) рекурсивно проверяет содержимое коллекций. simtypes намеренно предлагает меньший контракт: без автоматического enforcement, преобразования значений и просмотра элементов коллекции в базовом режиме.

Для одного места вызова лучшим решением всё ещё может оказаться локальная функция поверх `isinstance()` и `typing.get_origin()`. Пакет становится полезен, когда одна и та же скромная политика должна тестироваться, версионироваться и использоваться несколькими библиотеками.

## Для чего предназначен simtypes

simtypes предназначен для runtime-инфраструктуры, которой нужна недорогая проверка совместимости, а не полноценный фреймворк валидации. Диспетчеризация, регистрация плагинов и конфигурационный код могут разделять одно правило без подключения системы enforcement и связывания своих архитектур.

## Что дальше

Проект будет охватывать больше практических runtime-типов и необязательных задач преобразования, сохраняя недорогую и явную проверку по умолчанию. simtypes останется сосредоточен на свойствах, наблюдаемых во время выполнения, и не будет пытаться воспроизвести полноценную статическую систему типов.
