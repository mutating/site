Мутационному тестированию и другим инструментам анализа исходного кода часто нужно найти все возможные правки в Python-файле, но применять их по одной. Если объединить несколько правок, их уже нельзя независимо тестировать или распределять как отдельные задачи. Обычные трансформеры деревьев заменяют все подходящие узлы за один проход и напрямую такой сценарий не поддерживают.

[LibCST](https://libcst.readthedocs.io/) сохраняет форматирование и комментарии, но его visitors и transformers сами по себе не превращают каждую возможную правку в независимо адресуемую операцию. Полноценные мутационные системы вроде [mutmut](https://github.com/boxed/mutmut) дополнительно управляют запуском тестов и сессиями мутаций. Отдельный слой преобразований нужен, когда инструменту требуется точность LibCST и независимые изменения без подключения целого mutation runner.

[cstvis](https://github.com/mutating/cstvis) — Python-библиотека поверх LibCST именно для такого сценария. Она находит привязанные к исходному коду координаты преобразований и позволяет независимо воспроизвести любое одно из них на исходном модуле. [Релиз](https://github.com/mutating/cstvis/releases/tag/0.0.1) доступен на GitHub.

## Обнаружение независимых преобразований

cstvis не заменяет парсер или API преобразований LibCST. Он координирует возможные правки, чтобы вызывающий код мог сначала перечислить их, а затем применить одну выбранную.

Конвертер — обычная функция, зарегистрированная через `@changer.converter`. Аннотация первого параметра выбирает конкретный тип узла LibCST. Фильтры решают, подходит ли отдельное вхождение. `iterate_coordinates()` выдаёт прошедшие отбор кандидаты как диапазоны в исходнике; `apply_coordinate()` начинает с нетронутого модуля и возвращает полный текст, где изменено только выбранное вхождение.

```python
from libcst import Add, Subtract
from cstvis import Changer

changer = Changer("total = left + right")

@changer.converter
def replace_add(node: Add, context):
    return Subtract(
        whitespace_before=node.whitespace_before,
        whitespace_after=node.whitespace_after,
    )

coordinate = next(changer.iterate_coordinates())
print(changer.apply_coordinate(coordinate))
#> total = left - right
```

В отличие от обычного трансформера, cstvis считает каждый подходящий узел независимым кандидатом. Два сложения в файле дают двух кандидатов, и каждый из них применяется отдельно к исходному тексту.

Контекст также содержит координату кандидата, комментарий на начальной строке узла и разобранные metacode-директивы. Поэтому каждый конвертер может использовать локальные правила, не реализуя поиск комментариев самостоятельно.

## Сравнение с другими инструментами преобразования

Прямые [visitors, transformers, matchers и codemods LibCST](https://libcst.readthedocs.io/en/latest/codemods.html) выразительнее и остаются лучшим выбором для сложного многошагового рефакторинга.

[Bowler](https://pybowler.io/) и [RedBaron](https://redbaron.readthedocs.io/) предлагают более высокоуровневые сценарии рефакторинга с сохранением исходного оформления. Стандартный [`ast.NodeTransformer`](https://docs.python.org/3/library/ast.html#ast.NodeTransformer) проще, если форматирование и комментарии сохранять не нужно.

cstvis специализируется на меньшем слое: преобразованиях LibCST с регистрацией по типам, доступом к комментариям исходного кода и независимым воспроизведением через API, не привязанный к runner-у.

## Для чего предназначен cstvis

cstvis занимается только преобразованиями. Он не обходит директории, не хранит сессии, не запускает тесты и не распределяет задачи. Координата может служить единицей работы для другой системы.

Модель допускает один конвертер на точный тип CST-узла и всегда применяет координаты к неизменённому исходнику. Эти ограничения делают результат каждой операции предсказуемым.

## Что дальше

Основное направление — упростить описание, объединение и повторное использование независимых преобразований. Более ясное разделение обнаружения и исполнения поможет другим инструментам строить крупные процессы без отказа от модели «одно изменение за раз».
