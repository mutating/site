Мутационному тестированию нужно найти все возможные правки в Python-файле, а затем независимо применить и проверить каждую. Обычные трансформеры деревьев заменяют все подходящие узлы за один проход и не дают такого разделения.

[LibCST](https://libcst.readthedocs.io/) сохраняет форматирование и комментарии, но не делает возможные правки независимо адресуемыми. Полноценные системы вроде [mutmut](https://github.com/boxed/mutmut) добавляют запуск тестов и управление сессиями. Между ними полезен меньший слой преобразований.

[cstvis](https://github.com/mutating/cstvis) — Python-библиотека поверх LibCST именно для такого сценария. Она находит привязанные к исходному коду координаты преобразований и позволяет независимо воспроизвести любое одно из них на исходном модуле. [Релиз](https://github.com/mutating/cstvis/releases/tag/0.0.1) доступен на GitHub.

## Обнаружение независимых преобразований

cstvis не заменяет парсер или API преобразований LibCST. Он координирует возможные правки, чтобы вызывающий код мог сначала перечислить их, а затем применить одну выбранную.

Функция с `@changer.converter` обрабатывает тип узла LibCST, указанный в аннотации первого параметра. Фильтры удаляют неподходящие вхождения. `iterate_coordinates()` возвращает оставшиеся диапазоны, а `apply_coordinate()` применяет один диапазон к нетронутому модулю.

```python
from libcst import Add, Subtract
from cstvis import Changer

changer = Changer("total = left + right")

@changer.converter
def replace_add(node: Add, context):
    return Subtract(
        whitespace_before=node.whitespace_before,
        whitespace_after=node.whitespace_after,
    )

coordinate = next(changer.iterate_coordinates())
print(changer.apply_coordinate(coordinate))
#> total = left - right
```

Поэтому два сложения дают двух кандидатов, и каждый применяется отдельно к исходному тексту.

Контекст содержит координату, комментарий на первой строке узла и разобранные metacode-директивы, поэтому конвертеру не нужно самостоятельно искать комментарии.

## Сравнение с другими инструментами преобразования

Прямые [codemods LibCST](https://libcst.readthedocs.io/en/latest/codemods.html) остаются лучшим выбором для сложного многошагового рефакторинга.

[Bowler](https://pybowler.io/) и [RedBaron](https://redbaron.readthedocs.io/) предлагают более высокоуровневые сценарии рефакторинга с сохранением исходного оформления. Стандартный [`ast.NodeTransformer`](https://docs.python.org/3/library/ast.html#ast.NodeTransformer) проще, если форматирование и комментарии сохранять не нужно.

cstvis специализируется на меньшем слое: преобразованиях LibCST с регистрацией по типам, доступом к комментариям исходного кода и независимым воспроизведением через API, не привязанный к runner-у.

## Для чего предназначен cstvis

cstvis не обходит директории, не хранит сессии, не запускает тесты и не распределяет задачи. Он допускает один конвертер на точный тип CST-узла и всегда применяет координаты к исходному тексту; другая система может использовать каждую координату как единицу работы.
