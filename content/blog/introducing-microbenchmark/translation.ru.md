Быстрый пример с `timeit` написать легко, но он перестаёт быть удобным, когда нескольким небольшим измерениям нужны имена, общий запуск, машиночитаемые результаты и простой порог ошибки. Самописные скрипты трудно сравнивать и автоматизировать, а полноценные системы бенчмарков могут требовать больше настройки и статистической инфраструктуры, чем нужно для точечной проверки библиотеки.

[`timeit`](https://docs.python.org/3/library/timeit.html) предоставляет надёжные средства измерения, но не даёт переиспользуемой модели именованных сценариев, групп, сериализации и бюджета для CI. [pyperf](https://pyperf.readthedocs.io/) и [pytest-benchmark](https://pytest-benchmark.readthedocs.io/en/latest/) предлагают статистически более строгие средства, изоляцию workers и анализ регрессий. Между ними остаётся место для небольшого in-process API, когда проекту нужны структурированные измерения без полноценной системы бенчмарков.

[microbenchmark](https://github.com/mutating/microbenchmark) — лёгкая Python-библиотека для структурированных измерений небольшого масштаба. Она представляет сценарии, группы и результаты бенчмарков обычными Python-объектами, которые можно объединять, исследовать, сериализовать и проверять по простому бюджету производительности. [Релиз](https://github.com/mutating/microbenchmark/releases/tag/0.0.1) доступен на GitHub.

## Основной API

`Scenario` хранит callable, позиционные аргументы, имя, документацию и число наблюдений вместе. `run()` выполняет необязательные прогревочные вызовы, а затем отдельно измеряет каждое выполнение через `perf_counter()` по умолчанию.

```python
from microbenchmark import Scenario

def build_list():
    return list(range(1000))

scenario = Scenario(build_list, name="build_list", number=500)
result = scenario.run()

print(result.mean)
print(result.best)
print(result.worst)
```

Описание бенчмарка и исходные замеры остаются Python-объектами, поэтому вызывающий код может исследовать и объединять их без разбора консольного вывода.

Получается `BenchmarkResult`, сохраняющий все длительности вместо немедленного сведения запуска к одному числу. Он предоставляет среднее, лучший и худший результаты. Свойства `p95` и `p99` возвращают усечённые наборы — самые быстрые 95 или 99 процентов замеров, — а не привычные скалярные перцентили задержки.

Сценарии компонуются как значения. Сложите два — получите плоский упорядоченный `ScenarioGroup`. Результаты сериализуются в JSON, чтобы другой процесс мог исследовать сырые наблюдения. Восстановленный результат намеренно не реконструирует сам исполняемый сценарий.

Тот же объект способен открыть небольшой CLI из benchmark-скрипта. `--number` меняет размер запуска, а `--max-mean` завершает программу с ошибкой при превышении бюджета среднего времени. Скрипт сам вызывает `.cli()`; отдельная команда вместе с microbenchmark не устанавливается.

Библиотека типизирована и не имеет runtime-зависимостей.

## Альтернативы и компромиссы

[`timeit`](https://docs.python.org/3/library/timeit.html) остаётся правильным выбором для разового измерения. Группировка операций и автоматический подбор длительности также уменьшают влияние самого таймера.

[pyperf](https://pyperf.readthedocs.io/) лучше подходит для строгих измерений: он калибрует циклы, использует worker-процессы, собирает metadata и делает статистические сравнения. [pytest-benchmark](https://pytest-benchmark.readthedocs.io/en/latest/) добавляет в pytest богатую статистику и проверки регрессий. [Airspeed Velocity](https://asv.readthedocs.io/) отслеживает производительность по коммитам и окружениям.

Отдельное измерение каждого вызова делает наблюдения обозримыми, но увеличивает влияние таймера и самого вызова Python-функции. Здесь нет автоматической калибровки, изоляции процессов или сравнения с baseline. `--max-mean` полезен как smoke test, но чувствителен к железу и нагрузке CI.

## Для кого предназначен microbenchmark

Главный пользователь — автор библиотеки, которому нужны несколько читаемых и переиспользуемых performance-сценариев рядом с измеряемым кодом. Маленькие парсеры, преобразования, сериализаторы, dispatch-операции и планировочные helpers могут использовать единый формат результатов. Для экспериментов с более строгими статистическими требованиями лучше выбрать полноценную систему бенчмарков.

## Что дальше

Проект будет упрощать работу с benchmark-сценариями из Python и командной строки и делать результаты понятнее. microbenchmark останется лёгким инструментом для структурированных измерений и не превратится в полноценную систему статистического бенчмаркинга.
