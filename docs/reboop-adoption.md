# Подключение reboop и проверка HTTP-запросов

Платформа и главный сайт используют опубликованный `reboop@0.1.34` из npm.
Проверка исходников использует `reboop-eslint@0.1.34`; соседний репозиторий
библиотеки не нужен ни для установки, ни для сборки, ни для CI.

## Транспорт платформы

`platform/web/src/lib/api.ts` сохраняет интерфейсы `api`, `request`, `apiBlob`,
`json` и `allPages`. Все их потребители получают новый транспорт без изменений
страниц. `ApiImage` также загружает изображения через этот модуль.

Общий клиент вызывает `reboop.read`: JSON, бинарное тело и `X-Total-Count`
читаются внутри попытки. Ручной цикл повторов и таймер успешного запроса удалены.

- GET/HEAD повторяются при сетевой ошибке и тайм-ауте без ограничения числа попыток.
  Паузы: 1, 2, 4, 8, затем 10 секунд; случайный разброс не добавляется.
- Лимит попытки, включая чтение тела, — 20 секунд. Индивидуальный бюджет
  обнаружения GitHub-репозиториев остаётся 90 секунд.
- POST/PUT/PATCH/DELETE отправляются один раз: после потери ответа запись
  могла уже сохраниться. HTTP-ошибки и некорректный JSON не повторяются.
- `AbortSignal` отменяет соединение, чтение и ожидание следующей попытки;
  вызывающая сторона получает исходную причину отмены.
- Сохраняются API-префикс и query-параметры, cookies, CSRF-заголовок,
  переопределение заголовков, JSON и бинарные загрузки, HEAD/204 и пагинация.
- `HTTPError` преобразуется в прежний `ApiError` с HTTP-статусом и строковым
  `detail`. Поскольку библиотека возвращает тело HTTP-ошибки вне `read`, его
  необязательное чтение отдельно ограничено бюджетом запроса; по истечении
  этого срока соединение закрывается, а известный статус сохраняется.
- Очередь изменения session-cookie, Web Locks и защита новой сессии от
  устаревших 401 остаются в адаптере платформы.

Главный сайт использует `reboop.text` для SVG пантографа с прежним URL,
`cache: "no-store"` и сигналом отмены. Это последний HTTP-вызов вне API-адаптера.
Для автономной сборки Hugo bootstrap передаёт подготовленные по lockfile
production-зависимости; параметры описаны в [инструкции деплоя](deployment.md).

IP-адресов в клиентском коде нет. DNS и выбор соединения остаются за браузером;
ретраи не гарантируют выбор другого IP.

## Установка и запуск

Из корня репозитория, с Node.js 24:

```sh
npm ci
npm run test:lint
npm run lint
npm run test:web:unit
npm run build:web
npm run build:site
```

`postinstall` также устанавливает инструменты по отдельному
`tools/http-lint/package-lock.json`. После установки с `--ignore-scripts`
этот шаг нужно выполнить явно:

```sh
npm ci --prefix tools/http-lint --ignore-scripts
```

Весь набор парсера изолирован в самостоятельном private-пакете `tools/http-lint`.
Сайт, UI и корневые команды продолжают использовать TypeScript 7.0.2.
`@typescript-eslint/parser@8.72.1` поддерживает TypeScript до 6.1 и использует
свою TypeScript 6.0.3. Изоляция распространяется и на транзитивные зависимости:
у TypeScript 7 отсутствует Compiler API, который использует `ts-api-utils`.
Обходов peer dependencies через `--force` или `--legacy-peer-deps` нет.
Docker-сборки получают manifest и lockfile инструментов до корневого `npm ci`.

## Область проверки

`eslint.config.mjs` включает `reboop/require-client` как ошибку для собственных
JS/JSX/TS/TSX/MJS/CJS/MTS/CTS-файлов:

- `platform/web/src` — приложение, включая общие API-обёртки;
- `platform/web/public` — браузерные конфигурации и дизайн-прототипы;
- `packages/ui/src` и `packages/ui/demo` — UI-библиотека и примеры;
- `site/themes/mutating/assets` — исходники Hugo, включая ESM-модуль `site.js`.

JS из `platform/web/public` разбирается как classic scripts, исходный JS Hugo —
как модули. Сборочные артефакты, временные каталоги и тестовые транспорты исключены.
Комментарии `eslint-disable` не отключают проверку.

В CI задание `HTTP client lint` выполняет тесты конфигурации и сам линтер.
После миграции линтер проходит без исключений для API-адаптера или SVG-загрузки.
Независимая AST-инвентаризация 70 JS/TS-файлов и 8 исполняемых встроенных
скриптов HTML/SVG не нашла оставшихся нативных HTTP-вызовов, других HTTP-клиентов
или динамического исполнения через `eval`/`Function`.

Загрузка браузером `script`, `img`, шрифтов и стороннего счётчика не является
вызовом HTTP-клиента приложения. Серверный Python-код не проверяется ESLint.

## Регрессионные проверки

`tests/lint/reboop.test.mjs` проверяет реальный ESLint и конфигурацию сайта:
охват исходников и синтаксиса, вызов внутри обёртки, разрешённый `reboop`,
локальные имена, запрет inline-подавлений, исключение артефактов и сохранение
компилятора приложения.

Тесты API находятся в `tests/platform/web/unit/api-*.test.ts`. Кроме управляемых
таймеров и ошибок браузеров, `api-network.test.ts` открывает настоящий локальный
HTTP-сервер: обрывает соединение до заголовков и после их получения посреди JSON
или изображения, проверяет восстановление и закрытие зависшего тела HTTP-ошибки.

Браузерная проверка с настоящим локальным API:

```sh
npm exec --workspace platform/web -- playwright test dashboard.spec.ts recovery.spec.ts user-menu.spec.ts actions-session-edge.spec.ts
npm exec -- playwright test -c tests/site/header/playwright.config.ts http-client.spec.ts
```

Первая команда проверяет 300 сценариев в Chromium desktop/mobile, Firefox,
WebKit и iPhone: вход/выход, cookies, CRUD, аватары, сетевые сбои и гонки сессий.
Вторая собирает Hugo и проверяет восстановление SVG после обрыва и терминальный
HTTP-отказ. Новые тесты сопровождаются док-комментариями; направленные мутации
проверяют, что они замечают отключение повторов, потерю отмены/дедлайнов,
заголовков, тел, метаданных, HTTP-ошибок и защиты сессий.
