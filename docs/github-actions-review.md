# Повторное ревью Actions

**Актуальная схема с 19 октября 2026:** только Power Cells. Нет свободного Mac —
немедленный отказ без VM/JIT; ошибки API/подготовки завершают routing и весь workflow
с failure, основной job пропускается. Политика fallback и её UI удалены. Routing
остаётся hosted: нужны hosted минуты. Требуйте routing check в защите ветки.
Существующий YAML необходимо заменить новым примером целиком. Упоминания прежней
схемы и ссылки на её прогоны ниже — история проверок, не текущая инструкция.


Ревью ограничено новой функциональностью Actions и регрессиями, которые она
вызвала. Каждую итерацию выполняют три независимых агента: безопасность;
планировщик/lifecycle; интерфейс/workflow/контракт агента. Они читают код и
проверяют поведение, не изменяя рабочие файлы. Основной агент перепроверяет
замечания, исправляет подтверждённые причины и добавляет регрессионные тесты
с предварительно сформулированными утверждениями.

Критерий завершения: две последовательные итерации, в каждой все трое
вернули 0 полезных замечаний. Отсутствие настоящего GitHub job из-за billing
не считается самостоятельным замечанием ревью.

## Исправления первой итерации

- Права `execution.read` фильтруются SQL до пагинации привязок.
- Допустимые Job ID сохраняют строковый тип в YAML, включая `null` и `true`.
- Запрашиваемая JIT-метка и `runs_on` совпадают: только уникальная метка.
  Общая `self-hosted` не добавляется: она расширила бы множество jobs,
  которые GitHub может назначить этому runner.
- Отмена/ошибка OAuth проверяет и потребляет state, возвращает в Actions с
  локализованным allowlisted сообщением и сохраняет существующее подключение.
- Неверная подпись webhook, включая произвольные не-ASCII байты, возвращает 401.
- Точки внутри имени репозитория разрешены; traversal запрещён по сегментам пути.
- Подтверждённый отзыв GitHub admin останавливает готовую/выбранную/работающую
  резервацию. Временные сбои не объявляются отзывом прав работающего job.
- После disable свежая выдача JIT запрещена сразу, без ожидания controller tick.
- Polling учитывает GitHub conclusion. Предварительный результат выхода runner
  уточняется поздним webhook или запросом конкретного workflow attempt;
  отмены и timeout при этом не возобновляются.

Регрессии находятся в
[API review tests](../tests/platform/api/e2e/powercell/test_ci_review.py),
[Actions browser tests](../tests/platform/web/e2e/actions-coverage.spec.ts),
а соответствие зарегистрированных и выбранных меток дополнительно проверяется
[сквозным стендом](../tests/platform/api/e2e/powercell/ci_chain_peer.py).

## Исправления второй итерации

- Disconnect или замена подключения инвалидирует незавершённое создание привязки.
- Приватный одноразовый OAuth claim позволяет disconnect/новому flow отозвать
  уже начавшийся обмен кодом, сохраняя запрет повторного использования state.
- Отсутствующий исторический run не блокирует удаление runner; временная ошибка
  получения результата сохраняет retry, но также не блокирует очистку.
- 404 конкретного ephemeral runner не объявляется отзывом GitHub прав:
  после selection результат остаётся предварительным для позднего completion.
- Сгенерированные routing jobs имеют разные ID для разных привязок одного workflow.
- YAML, UI и API docs требуют upstream needs и approval/concurrency gates до routing;
  выбранный runner по-прежнему ограничен пятью минутами ожидания job.
- Сериализация локального журнала Mac исключает JIT из env, сохраняя полный
  исходный task в памяти для запуска. Это устранение ненужной персистенции,
  а не исправление обхода авторизации на доверенном Mac.

## Исправления третьей итерации

- Активный polling читает конкретный workflow attempt. Новый rerun не подменяет
  результат старого запуска, даже если completion ещё не дошёл до платформы.
- Неверная структура JSON ответа issuer/reserve/commit вызывает настроенный fallback
  и отмену подготовленной резервации; явные terminal failures и чужие метки
  остаются ошибками.
- UI не предлагает организации без `execution.read`: после создания их workflow
  и история иначе были бы недоступны. API policy создания не расширяется.
- Общая проверка управляемых Actions изолятов запрещает ручные mutations через
  обычный execution API, включая command enqueue/cancel, snapshots, renew и destroy.
  Это сохраняет исключительное управление средой CI и границы выдачи JIT.

Swift-регрессия и соседние проверки AgentLifecycle/Journal: 36 прошли; виртуальные
машины в этом прогоне не запускались.

## Исправления четвёртой итерации

- Routing output содержит `run_attempt`. Частичный rerun успешный router обычно
  не повторяет; guard не использует его старую метку. С fallback выбирается hosted
  runner, с `none` workflow останавливается до выделения машины и требует повторить
  routing job с зависимыми jobs или весь workflow.
- Страхующий polling долгих jobs и поздних результатов делит бюджет installation:
  интервал `max(30, 12 × N)` секунд, где N — число незавершённых резерваций её routes.
  Steady polling ограничен 300 проходами/час на installation (до 2700 HTTP при
  текущей стоимости 9 запросов/проход), отдельно от коротких bursts подготовки
  и первой очистки. Ошибки не уменьшают интервал, terminal переход ускоряет cleanup.
  Webhooks и локальные deadlines продолжают обрабатываться сразу.

## Уточнение пятой итерации

OIDC разрешает резервирование конкретному workflow/ref/attempt, однако сам JIT
runner GitHub регистрирует на репозиторий и назначает jobs по меткам. Поэтому
прежнее безоговорочное обещание отсутствия доступа у PR было слишком широким:
bootstrap отправляет PR в fallback, но не является отдельной политикой назначения
GitHub. Уникальная метка не должна считаться секретом.

Контракт и UI теперь явно включают в доверенную границу пула всех авторов jobs
репозитория, включая допущенные PR. Это исправление неверной гарантии и описание
реального ограничения архитектуры, **не** добавление run-bound isolation и не
заявление о воспроизведённой атаке. Предложенный простой job-start hook не добавлен:
его failure не является надёжной защитой от последующих `if: always()` steps.

Основания: [GitHub job metadata](https://docs.github.com/en/rest/actions/workflow-jobs),
[runner authentication/assignment](https://github.com/actions/runner/blob/main/docs/design/auth.md).

## Исправления шестой итерации

- API и UI согласованы с контрактом единственного поддерживаемого Power Cell:
  RAM не меньше 16 MiB, диск не больше 1 TiB. Невыполнимые параметры отклоняются
  до создания изолята, а граничные значения принимаются.
- Бюджет R4 распространён на все terminal reservations: offline Mac не вызывает
  бесконечный GitHub cleanup каждые пять секунд. Сохраняется ранняя контрольная
  проверка после 60-секундного окна поздней регистрации; локальные ресурсы
  по-прежнему удерживаются до подтверждения уничтожения.
- Исправлено устаревшее ожидание независимости snippets после добавления attempt
  guard: тест сохраняет исходные утверждения о непересекающихся router IDs и
  outputs каждой привязки, учитывая новый обязательный guard.

## Исправления седьмой итерации

- Общий переход в running проверяет срок selection, preparation deadline для ready,
  lifetime и состояние изолята. Подписанный поздний start webhook и задержавшийся
  busy poll больше не продлевают уже истёкший ресурс. Нормальный своевременный
  старт из ready/selected по-прежнему поддерживается.
- Ссылки истории содержат `/attempts/{run_attempt}`. Подпись старой попытки
  больше не ведёт в Latest после повторного запуска того же GitHub run ID.

## Исправления восьмой итерации

- Commit и переход в running используют общую проверку VM, команды runner и
  назначенной сессии компьютера в одном SQL-запросе. Известные failure/completion,
  истёкшие lifetime/agent lease и смена сессии больше не публикуют мёртвую метку
  до следующего CI tick; обычный повтор commit остаётся идемпотентным.
- Active reconciliation использует актуальное имя из проверки repository ID.
  Terminal cleanup получает каноническое имя через App metadata по тому же ID,
  сохраняя возможность очистки после OAuth disconnect. Redirect не включается;
  ID и имя ответа валидируются перед credentialed runner-запросами.
- Для новых запусков после rename/transfer нужна новая привязка: OIDC всё ещё
  закреплён за именем/owner/ref исходной политики. Текущая очистка от старого имени
  больше не зависит.

## Результат повторного ревью

Проведены 10 итераций по три независимых сабагента. Итерации 9 и 10 подряд дали
0/0/0 новых полезных замечаний; условие завершения ревью выполнено. Подтверждённые
причины исправлены в рабочем дереве; изменения сервера и установка приложения
этим ревью не выполнялись.

Результаты итоговых автоматических проверок фиксируются в
[отчёте тестирования](github-actions-testing.md). Настоящий GitHub job по-прежнему
не подтверждён из-за внешней billing-блокировки; ни один из локальных мок-прогонов
не выдаётся за выполнение CI в настоящем GitHub или VM.

До исправления основной агент повторно получил **16 failed / 20 passed** в

промежуточно прошли 169 API cases и 6 браузерных запусков новых регрессий.

## Аудит внешних контрактов GitHub, 18 октября 2026 года

Отдельный цикл по запросу о поведении самого GitHub. В каждом раунде работают
три независимых ревьюера: идентификация/полномочия/лимиты, lifecycle/события,
workflow/runner/bootstrap. Замечания сверяются с актуальной официальной
документацией и независимо воспроизводятся основным агентом до исправления.
Новые возможности и изменения схемы БД в этот цикл не входят.

| Раунд | Полномочия и лимиты | События и lifecycle | Workflow и runner | Результат |
| --- | --- | --- | --- | --- |
| 1 | 2 | 1 | 1 | Четыре подтверждённых замечания; новые регрессии первоначально дали 46 failed / 7 passed |
| 2 | 2 | 0 | 0 | Воспроизведены сокращение cooldown параллельным ответом и ложный отзыв доступа при ротации OAuth |
| 3 | 0 | 0 | 0 | Первая полностью чистая итерация внешних контрактов |
| 4 | 0 | 0 | 0 | Вторая полностью чистая итерация подряд; условие завершения выполнено |

Подтверждённые контракты:

- GitHub [не повторяет неудачные webhook автоматически](https://docs.github.com/en/webhooks/testing-and-troubleshooting-webhooks/redelivering-webhooks).
  Контроллер восстанавливает точный результат по
  [jobs исходного attempt](https://docs.github.com/en/rest/actions/workflow-jobs#list-jobs-for-a-workflow-run-attempt),
  включая пагинацию и проверку runner ID/имени. Обязательная очистка runner
  предшествует необязательному запросу результата.
- [Отзыв пользовательской авторизации](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app)
  приходит обязательным событием `github_app_authorization`; теперь оно прекращает
  локальные полномочия, включая уже начатые OAuth exchange/refresh.
- [Rate limit](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api#rate-limit-errors)
  возвращается как 403 или 429. Общая задержка следует Retry-After/reset и не
  обходится ротацией user/installation token; обычный permission 403 обрабатывается
  отдельно. Отставший успешный ответ не снимает более новое ограничение.
- Workflow [наследует рабочий каталог](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#defaultsrunworking-directory).
  Routing использует существующий `runner.temp`, поэтому может стартовать до
  checkout в монорепозитории с `defaults.run.working-directory`.

Дополнительная регрессия основного агента воспроизвела гонку старого успешного
ответа и нового rate limit: 1 failed / 1 passed до исправления. Тесты результата
job также проверяют, что повторное уточнение не переносит время завершения
и не откладывает очистку бесконечно. После исправлений первый целевой прогон:
**55 passed**. Последующие раунды и итоговые проверки фиксируются ниже.

Во втором раунде основной агент воспроизвёл сокращение cooldown восемью
вариантами статусов/порядка ответов: **4 failed / 4 passed** до исправления.
Ни одна более короткая задержка теперь не заменяет ещё действующий длинный
срок reset. После изменения **22 rate-limit unit cases passed**.

При [refresh GitHub немедленно инвалидирует предыдущий access token](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/refreshing-user-access-tokens#about-user-access-tokens-that-expire).
Задержавшийся запрос с прежним токеном поэтому мог получить 401 и ошибочно
отменить выполняющийся CI, хотя обновлённая авторизация продолжала действовать.
Новые регрессии и защитные проверки сначала дали **7 failed / 5 passed**;
пользовательские GET теперь повторяются однократно только с изменившимся токеном.
Администрирование репозитория проверяется заново, настоящий 401, disconnect и
revocation остаются отказом. Полный первоначальный прогон **458 passed / 1 failed**
дополнительно поймал перезапись точного webhook устаревшим REST ответом; callback
теперь сверяет исходную причину завершения перед записью. Общий повтор этих
проверок с соседними существующими регрессиями: **16 passed**.

Цикл завершён после четырёх раундов и 12 независимых ревьюеров. Раунды 3 и 4
дали 0/0/0 подряд. Шесть замечаний о внешних контрактах подтверждены; новые
регрессии также обнаружили и закрыли гонки при реализации исправлений. Runtime
изменён в шести API-файлах, без новых зависимостей, схемы БД или возможностей.

Итоговый полный целевой прогон: **479 API/protocol cases passed**, из них
75 новых проверок на моках. Ruff, format, D103 новых тестов и `git diff --check`

шести перечисленных API-файлов и manifest; frontend и статический сайт сохранены.
